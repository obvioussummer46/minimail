## 1. Purpose & scope

### 1.1 What this module delivers

1. **One authoritative fixture catalog.** Two `CATALOG.txt` files (one per package test target) that list every committed fixture, plus a Linux-runnable checker (`scripts/check-fixtures.py`, `make fixtures-check`) that proves the files on disk are exactly the catalog, that every JSON parses, that the byte-exact MIME fixtures still match their `.sha256` siblings and their declared sizes, and that CRLF fixtures were not mangled by git. Generation notes for every fixture family live in `docs/plan/fixtures.md`.
2. **`minimailTests/Support/FixtureLoader.swift`** — the shared loader for the app test bundle (the package targets keep their own `Bundle.module` loaders from modules 02/03/08), with the folder-reference/flattened fallback of architecture §1.4.
3. **`minimailTests/SmokeTests.swift`** — architecture §13.1's hosting smoke layer: `InboxScreen`, `ThreadScreen`, `ComposeScreen`, `LabelsScreen`, `SettingsScreen` and `RootView` instantiated inside `UIHostingController` against a seeded in-memory database, asserting observable model state (row count, rendered document contains the seeded subject, prefilled recipients) and that hosting a screen performs **zero** network requests.
4. **`minimailTests/FixtureCatalogTests.swift`** — proves the catalog is complete and loadable from the **app** test bundle (the `project.yml` fixture copy of architecture §1.4 and its documented fallback).
5. **Test-support conventions** (§4.5): the rules every module's tests already follow, written down once — route tables (`StubURLProtocol`, `BatchStub`), seeds (`TestDatabase`), invariants (`InvariantChecks`), frozen clocks, injected randomness, naming, isolation, `AppEnvironment(testing: true)` wiring. Plus the two additive `TestDatabase` helpers the smoke tests need.
6. **The cross-module test matrix** (§4.6): every architecture §4.7 conflict row, every §13.3 app-test bullet and both §12.3 performance tests mapped to the owning test file and function, so a reviewer can verify coverage without re-reading thirteen specs.
7. **`docs/plan/device-checklist.md`** — the manual device pass of architecture §13.1 layer 4: every UNVERIFIED item of §14 that only a real device settles, with steps, expected outcome and the written fallback.
8. **The TestFlight runbook** — `make archive` / `make upload-testflight`, `ExportOptions.plist` verification, App Store Connect API key secrets, build-number policy, `.github/workflows/release.yml`, and `docs/plan/testflight-runbook.md`.
9. **`make qa`** — the single command that runs the whole automated gate: `core-test`, `fixtures-check`, `lint`, `test-app`.

### 1.2 Explicitly out of scope

- **Any production-code change.** This module touches no file under `minimail/` or `Packages/MailCore/Sources/`. The only production test hooks it uses (`AppEnvironment(testing:)`, `AppEnvironment.testURLProtocolClasses`, `AppEnvironment.isTestingProcess`, `MINIMAIL_TESTING=1`) were declared by modules 01/05/06 and are only *documented* here.
- **Changing the signatures of `StubURLProtocol` (05 §3.6), `TestDatabase` / `InvariantChecks` (06 §3.17) or `SyncTestSupport` / `BatchStub` / `JSONFixtures` (07 §3.x).** This module may only *add* members to `TestDatabase` (modules.md: "14 documents their conventions and may extend them").
- **Re-implementing tests owned by other modules.** The matrix of §4.6 references them; it does not duplicate them.
- **New fixtures for existing families.** Every fixture of architecture §13.2 is already owned by modules 02 (`mime/*`, `vectors/*`), 03 (`gmail/*`), 06 (`vectors/today.json`), 01 (`vectors/smoke.json`, `html/smoke.html`) and 08 (`html/*`). This module adds only the two `CATALOG.txt` files.
- **UI tests (XCUITest), snapshot tests, a CI launch-time gate, a Diagnostics screen, coverage thresholds** — architecture decision 15 / §15 D13 / §16. `[tooling §7.2, §7.3]` is deliberately not followed.
- **Free-provisioning distribution** (`[tooling §6.3]`) — the runbook documents it as a fallback paragraph only.

### 1.3 Milestone placement

`docs/plan/device-checklist.md` is created in **M2** (architecture §13.1 note) with the items modules 04/07/08/09/10/12 hand over; M3 adds the compose/send rows; M4 completes it, adds the TestFlight runbook and runs the pass. ### 3.1 `minimailTests/Support/FixtureLoader.swift`

```swift
import Foundation
import XCTest

/// Bundle anchor. `Bundle(for:)` needs a class; this one exists for nothing else.
nonisolated final class FixtureBundleAnchor {}

/// Errors thrown by the loader. `XCTSkip` is used instead for the "fixtures were not copied into the bundle at all" case,
/// so a mis-generated project reports a skip, not 60 failures (§4.1 step 5).
nonisolated enum FixtureError: Error, Equatable, CustomStringConvertible {
    /// The relative path is not in the bundle under `Fixtures/` nor flattened at the bundle root.
    case missing(String)
    /// `Fixtures/CATALOG.txt` is present but a line could not be parsed (§4.2).
    case malformedCatalog(line: Int, text: String)
    var description: String { get }
}

/// Loads the fixtures that `project.yml` copies from `Packages/MailCore/Tests/MailCoreTests/Fixtures` into the
/// `minimailTests` bundle (architecture §1.4). Package targets keep their own `Bundle.module` loaders
/// (`MailCoreTests/Support/Fixtures.swift`, `GmailFixtures.swift`, `MailHTMLTests/Support/HTMLFixtures.swift`) — this type
/// exists because a test bundle has no `Bundle.module` for another target's resources.
///
/// Thread-safety: every member is a pure function of the bundle contents; `bundle` and `root` are computed once into
/// `let`s inside an `enum` (immutable, `Sendable`). Safe from any isolation domain.
nonisolated enum FixtureLoader {

    /// `Bundle(for: FixtureBundleAnchor.self)` — the `minimailTests` bundle.
    static let bundle: Bundle

    /// `bundle.resourceURL!/Fixtures` when that directory exists (the `type: folder` copy), otherwise `nil`
    /// (the documented `excludes: ["**/*.swift"]` fallback of architecture §1.4 flattens the tree).
    static let root: URL?

    /// `true` when the fixtures were copied as a folder and directory enumeration is meaningful.
    static var isFolderCopy: Bool { root != nil }

    /// Resolves a catalog-relative path such as `"gmail/profile.json"`.
    /// 1. `root/<relativePath>` when `isFolderCopy` and the file exists.
    /// 2. `bundle.url(forResource:withExtension:subdirectory:)` with the path split into subdirectory/name/extension.
    /// 3. Flattened fallback: `bundle.url(forResource:withExtension:)` with the **last** path component only.
    /// - Throws: `FixtureError.missing(relativePath)` when all three fail.
    static func url(_ relativePath: String) throws -> URL

    /// `Data(contentsOf: url(relativePath))` — bytes exactly as committed (LF for text fixtures).
    static func data(_ relativePath: String) throws -> Data

    /// UTF-8 string of `data(_:)`; throws `FixtureError.missing` when the bytes are not valid UTF-8.
    static func string(_ relativePath: String) throws -> String

    /// `data(_:)` with every `\n` that is not already preceded by `\r` replaced by `\r\n`.
    /// Used for the wire-format fixtures (`gmail/batch.*.txt`) so `core.autocrlf` cannot break byte-exact tests
    /// (same rule as module 03's `GmailFixtures.crlf`).
    static func crlf(_ relativePath: String) throws -> Data

    /// `JSONDecoder().decode(T.self, from: data(relativePath))`.
    static func json<T: Decodable>(_ relativePath: String, as type: T.Type) throws -> T

    /// Convenience for the most common family: `data("gmail/" + name)`.
    static func gmail(_ name: String) throws -> Data

    /// Every file under `root`, as catalog-relative paths, sorted, excluding `CATALOG.txt` and dot-files.
    /// Empty when `!isFolderCopy`.
    static func filesInBundle() -> [String]

    /// Calls `XCTSkip` when neither `Fixtures/gmail/profile.json` nor a flattened `profile.json` is in the bundle,
    /// with the message "fixtures were not copied into minimailTests — check the project.yml folder reference
    /// (architecture §1.4 / §14 #24)". Called from `setUpWithError()` of every test class that reads fixtures.
    static func requireFixtures() throws
}

/// The committed catalog, parsed from `Fixtures/CATALOG.txt` in the test bundle (§4.2).
nonisolated enum FixtureCatalog {
    /// Expected counts — the numbers the catalog file must contain. A module that adds a fixture updates
    /// `CATALOG.txt` **and** these numbers; `FixtureCatalogTests.testCounts` is the tripwire.
    static let expectedGmailCount = 47
    static let expectedMimeCount = 9
    static let expectedVectorsCount = 9
    static let expectedTotalCount = 65          // gmail + mime + vectors, the MailCoreTests target
    /// The 9 `MailHTMLTests` fixtures; not present in the app bundle (§4.2 rule C4) — listed for `docs/plan/fixtures.md`
    /// and for `scripts/check-fixtures.py` parity only.
    static let htmlCount = 9

    /// Catalog-relative paths in file order, parsed from the bundled `Fixtures/CATALOG.txt`.
    /// - Throws: `FixtureError.missing("CATALOG.txt")`, `FixtureError.malformedCatalog(line:text:)`.
    static func entries() throws -> [String]

    /// `entries()` filtered by first path component ("gmail", "mime", "vectors").
    static func entries(family: String) throws -> [String]
}
```

```swift
import GRDB

extension TestDatabase {

    /// What `seedSmoke` wrote, so the smoke tests assert against values instead of literals.
    nonisolated struct SmokeSeed: Sendable, Equatable {
        /// `["t1", "t2", "t3"]`, newest first (t1 is the newest).
        let threadIds: [String]
        /// `"t1"` — the thread the smoke tests open.
        let openThreadId: String
        /// `"m1b"` — newest message of `t1`; the compose origin.
        let newestMessageId: String
        /// `"Quarterly report"` — subject of every message in `t1` (`thread.subject` after prefix stripping).
        let subject: String
        /// `"MM-SMOKE-BODY"` — a marker string inside the stored body HTML of `m1b`.
        let bodyMarker: String
        /// `Mailbox(name: "Alice Adams", addr: "alice@example.com")` — From of `m1b`.
        let sender: Mailbox
        /// `Mailbox(name: "Bob Brown", addr: "bob@example.com")` — Cc of `m1b`.
        let ccRecipient: Mailbox
        /// `"user@newtelco.de"` — the account address written into `syncState.selfAddresses`/`accountEmail`.
        let selfAddress: String
        /// `1_757_500_000_000` unless overridden — `internalDate` of `m1b`.
        let now: Int64
    }

    /// Seeds the fixture account the smoke tests share, in ONE write transaction:
    /// labels (`TestDatabase.sampleLabels`), `syncState` (`accountEmail`, `selfAddresses`, `displayName`,
    /// `historyId = "5000"`, `syncGeneration = "1"`), three threads (`t1` with two messages `m1a`/`m1b`,
    /// `t2` and `t3` with one each), a stored body + one PDF attachment row for `m1b`, and
    /// `ThreadRepository.markComplete(t1, complete: true)`.
    /// Aggregates are recomputed inside the same transaction, so `Queries.threads`/`threadDetail` are immediately correct.
    /// - Returns: the `SmokeSeed` describing what was written.
    @discardableResult
    static func seedSmoke(_ writer: any DatabaseWriter, now: Int64 = 1_757_500_000_000) throws -> SmokeSeed

    /// Stores a sanitized body for one existing message: `BodyRepository.storeBody(db, messageId:, body:
    /// SanitizedBody(html: html, hasRemoteImages: false, darkStrategy: .plain, referencedContentIDs: []),
    /// text: text, attachments: attachments, referenced: [], sanitizerVersion: Sanitizer.version, now: now)`
    /// followed by `ThreadRepository.recomputeAggregates` for the owning thread.
    static func seedBody(_ writer: any DatabaseWriter, messageId: String, html: String, text: String?,
                         attachments: [ParsedAttachment] = [], now: Int64 = 1_757_500_000_000) throws
}
```

## 4. Behaviour

### 4.1 `FixtureLoader.url(_:)` — resolution

Inputs: a catalog-relative path (`"gmail/profile.json"`, `"mime/reply-all.eml"`, `"vectors/today.json"`). Output: a `URL` inside the test bundle, or `FixtureError.missing`.

```
url(rel):
 1. if let root, FileManager.default.fileExists(atPath: root.appendingPathComponent(rel).path)
        → return that URL                                            // folder-reference copy (expected)
 2. split rel at the last "/": sub = prefix or nil, file = suffix
    split file at the last ".": name, ext
 3. if let u = bundle.url(forResource: name, withExtension: ext, subdirectory: sub.map { "Fixtures/" + $0 })
        → return u
 4. if let u = bundle.url(forResource: name, withExtension: ext)     // flattened fallback (architecture §1.4 / §14 #24)
        → return u
 5. throw FixtureError.missing(rel)
```

`root` is computed once: `bundle.resourceURL?.appendingPathComponent("Fixtures")`, kept only when `isDirectory == true`.

`requireFixtures()` runs steps 1–4 for `"gmail/profile.json"`; on failure it calls
`throw XCTSkip("fixtures were not copied into minimailTests — check the project.yml folder reference (architecture §1.4 / §14 #24)")`.
Rationale: a project-generation problem must not look like 60 broken assertions.

`crlf(_:)` converts with a single pass over the bytes: emit `0x0D 0x0A` for every `0x0A` whose predecessor is not `0x0D`; other bytes verbatim. Idempotent.

Performance: `filesInBundle()` uses `FileManager.default.enumerator(at:includingPropertiesForKeys:[.isRegularFileKey])`, skipping directories, `CATALOG.txt` and names starting with `.`; result sorted with `<`. Cost ≈ 65 stat calls, < 5 ms.

### 4.2 Catalog format and rules

`CATALOG.txt` grammar (both files):

```
line   := comment | blank | entry
comment:= "#" .*
blank  := ""
entry  := <family> "/" <filename>        # no leading "./", no "..", exactly one "/"
```

Parsing (`FixtureCatalog.entries()`): read `FixtureLoader.string("CATALOG.txt")` (resolved by the same rules as any fixture), split on `\n`, trim trailing `\r`, drop blanks and `#` lines, and validate each remaining line against `^[a-z]+/[A-Za-z0-9._-]+$`; a violation throws `FixtureError.malformedCatalog(line:text:)` with the 1-based line number.

Invariants the tests enforce:

| # | Rule | Enforced by |
|---|---|---|
| C1 | Every catalog entry resolves to a file in the app test bundle | `FixtureCatalogTests.testEveryCatalogEntryLoads` |
| C2 | Every file in the bundle's `Fixtures/` tree (minus `CATALOG.txt` and dot-files) is a catalog entry | `testNoOrphanFilesInBundle` (skipped when flattened) |
| C3 | Counts equal `FixtureCatalog.expected*Count` (47 / 9 / 9 / 65) | `testCounts` |
| C4 | The `MailHTMLTests` catalog is **not** loaded from the app bundle (`project.yml` copies only the `MailCoreTests` folder); it is checked on disk by `scripts/check-fixtures.py` and in `swift test` by module 08's `HTMLFixtures` | `scripts/check-fixtures.py` |
| C5 | Entries are sorted ascending inside a family and families appear in the order `gmail`, `mime`, `vectors` | `scripts/check-fixtures.py` (`--check-order`) |
| C6 | A module that adds/renames a fixture must update `CATALOG.txt` and, when a count changes, `FixtureCatalog.expected*Count` | C1–C3 fail otherwise |

### 4.3 `scripts/check-fixtures.py` — algorithm

Run as `python3 scripts/check-fixtures.py` from the repo root (Python 3.8+, standard library only; no network, no Xcode). Exit code 0 = pass, 1 = failures (each printed as `FAIL <check>: <detail>`), 2 = usage error.

```
ROOTS = [("Packages/MailCore/Tests/MailCoreTests/Fixtures", ["gmail", "mime", "vectors"]),
         ("Packages/MailCore/Tests/MailHTMLTests/Fixtures",  ["html"])]

for (root, families) in ROOTS:
 1. catalog = [non-comment, non-blank lines of root/CATALOG.txt]
 2. disk    = sorted(relative paths of every regular file under root,
                     excluding CATALOG.txt and names starting with ".")
 3. FAIL on catalog != disk, printing the two symmetric differences
 4. FAIL when any entry's first path component is not in families
 5. FAIL when catalog is not sorted within each family, or families appear out of order

then, content checks:
 6. every "*.json" parses with json.loads (UTF-8)                          -> FAIL "json"
 7. for every "*.eml": sha256(bytes) == the 64 hex chars of the sibling
    "<same stem>.sha256" (file content trimmed)                            -> FAIL "sha256"
 8. byte sizes (EXPECTED_SIZES): mime/reply-all.eml == 2276,
    mime/forward-pdf.eml == 2927, mime/forward-pdf-gmailweb.eml == 2971,
    mime/stub.pdf == 125                                                   -> FAIL "size"
 9. every "*.eml": b"\r\n" in bytes and no b"\n" that is not preceded by b"\r"  -> FAIL "crlf"
10. every "*.raw.txt": single line, no "\n", charset subset of
    [A-Za-z0-9_-] (unpadded base64url)                                      -> FAIL "raw"
11. every "gmail/batch.*.txt": contains b"\n" and NO b"\r\n"
    (committed LF; tests convert)                                           -> FAIL "lf"
12. every "*.html", "*.txt", "*.json", "*.eml", "*.sha256": decodes as UTF-8  -> FAIL "utf8"
13. mime/stub.pdf is 125 bytes (EXPECTED_SIZES, same check as step 8)         -> FAIL "size"
print "OK <n> fixtures in <m> roots"
```

Checks 7–13 are skipped for a file the catalog does not contain (step 3 already failed for it).

`make fixtures-check` runs the script; the `core` CI job runs it before `make core-test` so a mangled fixture is reported as a catalog failure rather than as 40 confusing decode failures.

#### 4.4.1 Shared setup

### 4.7 Device checklist — procedure

1. Preconditions: the owner's iPhone (iOS 17+), a TestFlight build from `make upload-testflight` (or a cable install), `Config/Google.xcconfig` filled with the real client id, the Workspace admin steps of `[gmail-api "OAuth scopes and Workspace policy"]` done.

### 4.8 TestFlight archive and upload

Inputs (environment variables, never committed): `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_PATH` (path to `AuthKey_<ASC_KEY_ID>.p8`), plus `Config/Signing.xcconfig` containing the real `DEVELOPMENT_TEAM` and `Config/Google.xcconfig` the real client id.

```
make upload-testflight
 1. make gen                          # xcodegen generate
 2. rm -rf .build/minimail.xcarchive
 3. xcodebuild archive  -configuration Release -destination 'generic/platform=iOS'
                        -allowProvisioningUpdates -authenticationKey{Path,ID,IssuerID}
 4. rm -rf .build/export
 5. xcodebuild -exportArchive -exportOptionsPlist ExportOptions.plist -exportPath .build/export
                        -allowProvisioningUpdates -authenticationKey{Path,ID,IssuerID}
      → ExportOptions `destination = upload` performs the App Store Connect upload in the same step [tooling §6.2]
 6. the build appears in App Store Connect → TestFlight → iOS builds, state "Processing" (minutes)
```

Preconditions checked by the runbook before step 1 (and by the release workflow as explicit steps):

- `xcodebuild -help | grep -A 60 exportOptionsPlist` lists every key used in `ExportOptions.plist` (architecture §14 / 01 A6: the key list is UNVERIFIED). A key rejected by the SDK is removed and the runbook records it.
- `grep -c REPLACE Config/Signing.xcconfig Config/Google.xcconfig` prints `0` for both (placeholders would produce an unsigned or mis-signed archive).
- `make qa` is green.
- `CURRENT_PROJECT_VERSION` is higher than the last uploaded build (`make bump-build`), unless `manageAppVersionAndBuildNumber` handles it; the runbook prescribes bumping explicitly so the number is reproducible from git.

Failure triage (runbook §5): "No signing certificate" → the ASC key lacks App Manager/Admin role or `-allowProvisioningUpdates` was dropped; "No profile for team" → `DEVELOPMENT_TEAM` placeholder; "The bundle version must be higher" → `make bump-build`; "Invalid Info.plist key" → a `UIBackgroundModes`/`BGTaskSchedulerPermittedIdentifiers` mismatch (architecture §1.4); "ITMS-90683 missing purpose string" → not applicable (minimail requests no privacy-scoped API); upload hangs → re-run step 5 only, the archive is reusable.

### 4.9 `make qa` and CI wiring

```
qa = core-test → fixtures-check → lint → test-app
```

Ordering: package tests first (seconds, catches most regressions), then the fixture gate (no toolchain), then lint, then the simulator suite (minutes). `make qa` on Linux stops at `test-app` (no `xcodebuild`); the runbook says to run `make core-test fixtures-check lint` on Linux and the full `make qa` on the macOS runner.

`ci.yml` change: in the `core` job, a `Fixture catalog` step running `make fixtures-check` is inserted **before** the "Package tests" step. It is not `continue-on-error`. The `ios` job is unchanged (it already runs `make lint`, `make core-test`, `make test-app`); `fixtures-check` is not repeated there because the checked files are platform-independent.

`release.yml` (new) runs only on `workflow_dispatch`, on `macos-26`, and performs: checkout → Xcode 26.6 → `brew install xcodegen` → write `Config/*.xcconfig` from secrets → write the `.p8` key into `$RUNNER_TEMP` → `make test-app` → `make upload-testflight` → always-run cleanup of the key file. It never runs on push (a TestFlight upload is a deliberate act).

```python
                continue
            if text.count("/") != 1 or text.startswith("/") or ".." in text:
                fail("catalog", "%s:%d malformed entry %r" % (path, number, text))
                continue
            lines.append(text)
    return lines


def scan(root):
    found = []
    for dirpath, dirnames, filenames in os.walk(root):
        dirnames[:] = [d for d in dirnames if not d.startswith(".")]
        for name in filenames:
            if name.startswith(".") or name == "CATALOG.txt":
                continue
            rel = os.path.relpath(os.path.join(dirpath, name), root).replace(os.sep, "/")
            found.append(rel)
    return sorted(found)


def check_content(root, entries):
    for rel in entries:
        path = os.path.join(root, rel)
        with open(path, "rb") as handle:
            data = handle.read()
        if rel.endswith((".json", ".txt", ".html", ".sha256", ".eml")):
            try:
                data.decode("utf-8")
            except UnicodeDecodeError as error:
                fail("utf8", "%s: %s" % (rel, error))
        if rel.endswith(".json"):
            try:
                json.loads(data.decode("utf-8"))
            except ValueError as error:
                fail("json", "%s: %s" % (rel, error))
        if rel.endswith(".eml"):
            if b"\r\n" not in data:
                fail("crlf", "%s: no CRLF found" % rel)
            for index, byte in enumerate(data):
                if byte == 0x0A and (index == 0 or data[index - 1] != 0x0D):
                    fail("crlf", "%s: bare LF at offset %d" % (rel, index))
                    break
            sidecar = os.path.join(root, rel[: -len(".eml")] + ".sha256")
            if os.path.exists(sidecar):
                with open(sidecar, "r", encoding="utf-8") as handle:
                    expected = handle.read().strip().split()[0]
                actual = hashlib.sha256(data).hexdigest()
                if actual != expected:
                    fail("sha256", "%s: %s != %s" % (rel, actual, expected))
            else:
                fail("sha256", "%s: missing sidecar %s" % (rel, os.path.basename(sidecar)))
        if rel.endswith(".raw.txt"):
            text = data.decode("utf-8").strip()
            if "\n" in text:
                fail("raw", "%s: must be a single line" % rel)
            illegal = [c for c in text if not (c.isalnum() or c in "-_")]
            if illegal:
                fail("raw", "%s: non-base64url characters %r" % (rel, sorted(set(illegal))[:5]))
        if rel.startswith("gmail/batch.") and rel.endswith(".txt"):
            if b"\r\n" in data:
                fail("lf", "%s: committed with CRLF; commit LF (tests convert)" % rel)
        if rel in EXPECTED_SIZES and len(data) != EXPECTED_SIZES[rel]:
            fail("size", "%s: %d bytes, expected %d" % (rel, len(data), EXPECTED_SIZES[rel]))


def main(argv):
    check_order = "--check-order" in argv[1:]
    total = 0
    for root, families in ROOTS:
        catalog_path = os.path.join(root, "CATALOG.txt")
        if not os.path.isfile(catalog_path):
            fail("catalog", "missing %s" % catalog_path)
            continue
        catalog = read_catalog(catalog_path)
        disk = scan(root)
        missing = [p for p in catalog if p not in disk]
        orphan = [p for p in disk if p not in catalog]
        for path in missing:
            fail("missing", "%s listed in CATALOG.txt but not on disk" % path)
        for path in orphan:
            fail("orphan", "%s on disk but not in CATALOG.txt" % path)
        for path in catalog:
            if path.split("/")[0] not in families:
                fail("family", "%s: unknown family for root %s" % (path, root))
        if check_order:
            order = {name: index for index, name in enumerate(families)}
            keys = [(order.get(p.split("/")[0], 99), p) for p in catalog]
            if keys != sorted(keys):
                fail("order", "%s: entries are not sorted by family then name" % catalog_path)
        check_content(root, [p for p in catalog if p in disk])
        total += len(catalog)
    if FAILURES:
        print("%d failure(s)" % len(FAILURES))
        return 1
    print("OK %d fixtures in %d roots" % (total, len(ROOTS)))
    return 0


if __name__ == "__main__":
    try:
        sys.exit(main(sys.argv))
    except OSError as error:
        print("error: %s" % error)
        sys.exit(2)
```

The file is committed with the executable bit set (`chmod +x`), but `make fixtures-check` invokes it through `python3` so the bit is not load-bearing.

7. **Fallback without the $99 membership** (`[tooling §6.3]`): free personal team, `-allowProvisioningUpdates DEVELOPMENT_TEAM=<personal>`, `xcrun devicectl device install app …`, re-install every 7 days; explicitly the worse path for a daily-driver mail client.
