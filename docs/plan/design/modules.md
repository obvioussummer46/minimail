# minimail — detailed-spec modules (from architecture.md, Appendix A)

Each module gets its own detailed spec. Scopes are exclusive: a file, type or behaviour belongs to exactly one module. "Must NOT contain" lines mark the boundaries where overlap is likely.

## 01-project-setup — Project, tooling, CI, app skeleton
Contains: `project.yml` (complete, §1.4), `Config/Signing.xcconfig` + `Config/Google.xcconfig`, `Makefile` (§1.6), `.swift-format`, `.gitignore`, `ExportOptions.plist`, `.github/workflows/ci.yml` (§1.7), `Packages/MailCore/Package.swift` (§1.5) with empty MailCore/MailHTML targets and test targets, `Resources/` (AppIcon, AccentColor, LaunchBackground light/dark, `PrivacyInfo.xcprivacy`), `App/MinimailApp.swift`, `App/AppEnvironment.swift` (composition root with the strict launch order of §12.2 and `testing:` mode), `App/RootView.swift` (routing on `AuthStore.State`), `Support/Log.swift` (logger categories + signposts), `Support/Formatters.swift`, `Theme/Theme.swift` + `Theme/ThemeStore.swift` (§10: protocol, tokens = system semantic colours, registry, `cssTokens(for:)`, `preferredColorScheme`, `forcedDocumentTheme`), `Features/Settings/Settings.swift` + `SettingsStore.swift` (§11 struct/store only). Public interface: `AppEnvironment`, `ThemeStore`/`Theme`/`ThemeTokens`, `SettingsStore`/`Settings`, `Log`. Must NOT contain: any screen other than a placeholder `RootView`, network, DB schema (only `Database.open` is called from `AppEnvironment` once module 06 exists — stub until then).

## 02-mailcore-mime — MailCore: encodings, headers, MIME builder, compose assembly
Contains (all in `Sources/MailCore`): `Encoding/{Base64URL,QuotedPrintable,RFC2047,RFC2231,Charsets}.swift`, `Headers/{Mailbox,AddressParser,HeaderDate,HeaderFolding,ContentTypeParams,MessageIDs}.swift`, `MIME/{OutgoingMessage,MIMEBuilder}.swift`, `Compose/{ComposeStyle,ReplyAll,SubjectPrefix,Quoting,OutgoingBodies,PlainTextHTML}.swift`, and their tests + `Fixtures/mime/*`, `Fixtures/vectors/*`. Public interface: exactly the signatures of §2.2 for those files. Must NOT contain: Gmail DTOs/parser/batch codec (03), anything importing SwiftSoup (08), sync logic (06/07), ThreadDocument (08).

## 03-mailcore-gmail-model — MailCore: Gmail DTOs, payload parser, batch codec
Contains: `Gmail/GmailDTO.swift` (all Codable shapes, `StringUInt64`/`StringInt64`, `GmailFormat`, `gmailMetadataHeaders`), `Gmail/MessageParser.swift` (`ParsedMessage`/`ParsedHeaders`/`ParsedBody`/`ParsedAttachment`, tree walk of `[mime-rfc §5.2]`, deferred text parts, `topMimeType`), `Gmail/BatchCodec.swift`; tests + `Fixtures/gmail/*.json`, `batch.*.txt`. Public interface: §2.2 Gmail section. Must NOT contain: HTTP (05), sanitising (08), storage mapping (06).

## 04-auth — AppAuth token actor, AuthStore, Keychain, sign-in screen
Contains: `Auth/{OAuthConfig,TokenProvider,AppAuthTokenProvider,AuthStore,Keychain}.swift`, `Features/SignIn/SignInScreen.swift`, `.onOpenURL` wiring in `MinimailApp`, sign-in/sign-out/reauth flows of §5 (single-flight refresh, `invalid_grant` → needsReauth, account-mismatch wipe hook, revoke), the §5.2 routing truth table, `KeychainTests`. Public interface: §2.4 Auth section. Must NOT contain: `GmailClient` (05) — `getProfile` after sign-in is invoked through an injected closure; DB wipe implementation (06, called via `AppEnvironment`).

## 05-gmail-client — GmailClient actor, error taxonomy, limiter, retries, batching
Contains: `Gmail/{GmailClient,GmailError,RequestLimiter,RequestLog}.swift`, `URLSession.minimail` configuration, `request(...)` with 401 refresh-once, retry table §6.2, batch runner §6.3 (chunk 25, per-part retry rounds, Content-ID matching), every endpoint of §2.4 including `modifyThreads`, `fields=` masks, `StubURLProtocol` and `GmailClientTests`. Public interface: `GmailClient`, `GmailError`, `RequestLimiter`, `RequestLog`, `ThreadModifyCall`. Must NOT contain: DB access, sync decisions (07), send idempotency logic (07).

## 06-storage — Schema, records, repositories, queries, label algebra, aggregator, day boundary
Contains: `Store/{Database,Schema,Records,Queries,MessageRepository,ThreadRepository,BodyRepository,LabelRepository,OutboxRepository,SyncStateRepository}.swift` implementing §3 verbatim and the repository signatures of §2.4 (including `enqueueModify` coalescing, `ackModify`, `discardModify`, `retryLater`, `releaseInFlight`, `rearmFailedModifies`, `staleIds`, `recomputeEffective`, `recomputeAggregates`), plus the pure MailCore files `Sync/LabelAlgebra.swift`, `Sync/OutboxCoalescer.swift`, `Sync/ThreadAggregator.swift`, `Support/DayBoundary.swift` (+ `RowDateLabel`) and their MailCore tests; app tests `DatabaseTests`, `RepositoryTests`, `QueriesTests`, `TestDatabase`, `InvariantChecks` (§3.5). Public interface: everything under "Store" in §2.4 plus `ThreadQuery`/`ThreadRow`/`ThreadDetail`. Must NOT contain: network, `SyncEngine`/`Outbox` actors (07), history reduction (07), UI.

## 07-sync-outbox — SyncEngine, HistoryReducer/HydrationPolicy, Outbox, MailActions, BG refresh, maintenance
Contains: MailCore `Sync/{HistoryReducer,HydrationPolicy,Backoff}.swift` + tests; `Sync/{SyncEngine,Outbox,MailActions,SyncStatus}.swift` implementing §4.1–§4.8 and §7.6–§7.7 (full/delta/resync/hydration/label views/load older/`ensureThreadLoaded` with `prepareBody`/label counts/badge; outbox claim–drain–ack–retry–rearm; `performSend` with `maybeSent` + `rfc822msgid:` and attachment fetch/re-resolve), `App/BackgroundRefresh.swift` (§4.10), `App/Maintenance.swift` (§4.9), scene-phase triggers in `MinimailApp`; app tests `SyncEngineTests`, `ResyncTests`, `OutboxTests`, `ConflictTests`, `SendTests`. Public interface: `SyncEngine`, `Outbox`, `MailActions`, `SyncStatus`, `SyncReason`, `BackgroundRefresh`, `Maintenance`. Must NOT contain: SQL (calls repositories only), sanitizer implementation (08; calls `Sanitizer.sanitize`), compose UI (11), MIME/quoting implementation (02).

## 08-html-rendering — MailHTML sanitizer, ThreadDocument template, WebViewHost, cid handler, link policy
Contains: `Sources/MailHTML/{Sanitizer,StyleScrubber,TrackingPixel,DarkStrategyClassifier,SignatureSanitizer,QuoteExtractor}.swift` (§9.1) + `MailHTMLTests` + `Fixtures/html/*`; MailCore `Render/ThreadDocument.swift` (§9.2 template, CSS with media-query + `data-theme` selectors, caps, `toggleScript`, `empty`) + tests; app `Web/{WebViewHost,MailWebView,WebBridge,CIDSchemeHandler,InlineImageStore,LinkPolicy}.swift` (§9.3–§9.6: configuration factory, rule lists JSON + compile/lookup, warm/recycle, throwaway instance, images-on swap with fallbacks, cid store with 2-in-flight cap and failure cache, stopped-task tracking), `WebViewHostTests`. Public interface: §2.3 and the Web section of §2.4. Must NOT contain: ThreadScreen/ThreadModel (10), attachment QuickLook (10), any SQL beyond `BodyRepository.attachment` reads via injected closures.

## 09-inbox-list — Inbox screen/model, rows, filters, swipe actions, banners, paging
Contains: `Features/Inbox/{InboxScreen,InboxModel,ThreadRowView,StatusBanner}.swift`: `NavigationStack` root, `ActiveSheet` enum and sheet presentation, `.toolbarTitleMenu` scope switching, unread toggle, `ValueObservation(.immediate)` of `Queries.threads` with `limit` paging (60/+60) and `loadOlder` triggers, `DayBoundary` refresh on `NSCalendarDayChanged`/`NSSystemTimeZoneDidChange`/scene active, pull-to-refresh, swipe actions with theme tints + `.sensoryFeedback`, empty states, Outbox section rows (Retry/Delete/tap → compose input), status banners (offline / error / reauth with sign-in action), `ThreadRoute` + `navigationDestination`. Public interface: `InboxScreen(scope:)`, `InboxModel`, `ThreadRoute`, `ActiveSheet`, `ComposeInput`. Must NOT contain: thread/compose/labels/settings screens (10–13), SQL (uses `Queries`), sync logic.

## 10-thread-view — Thread screen/model, actions bar, attachments/QuickLook, mark read
Contains: `Features/Thread/{ThreadScreen,ThreadModel,AttachmentOpener}.swift`: observation of `Queries.threadDetail`, `expanded`/`imagesAllowed` state, document build via `ThreadDocument.render` with theme CSS tokens and forced scheme, `revision`-driven reload rules, `evaluateJavaScript` toggle, "Load images" flow, `WebMessage` handling, bottom toolbar (Reply all / Forward / Archive-pop / Read-Unread via `MailActions`), `ensureThreadLoaded` + mark-read-on-open, attachment download (stored id first, one re-resolve on 404) to `tmp/attachments` + `.quickLookPreview`, link → `openURL`, recycle on disappear, Dynamic Type reload. Public interface: `ThreadScreen(threadId:)`, `ThreadModel`, `AttachmentOpener`. Must NOT contain: web-view configuration (08), compose prefill (11), sanitizing.

## 11-compose — Compose screen/model, draft prefill, quote snapshot, SendJob, failed-send reopen
Contains: `Features/Compose/{ComposeScreen,ComposeModel}.swift`: `makeDraft` (§7.2: ReplyAll, SubjectPrefix, MessageIDs chain, forward attachment refs, `QuoteSource` snapshot via `QuoteExtractor`, `quoteReady` gating), Form UI of §8.5 (To/Cc/Subject fields, `TextEditor`, attachment toggles with size budget, read-only `Text` quote preview), validation with `AddressParser`, `SendJob` construction (`messageID`, `includeSignature`), `MailActions.send` + immediate dismiss + haptic, reopening a failed send from an outbox row (delete old job on resend), cancel confirmation. Public interface: `ComposeScreen(input:)`, `ComposeModel`, `ComposeInput` handling. Must NOT contain: MIME building or the send network path (02/07), signature editing (13), a second WKWebView.

## 12-labels — Labels sheet/model, label view hydration wiring, counts throttle, chips
Contains: `Features/Labels/{LabelsScreen,LabelsModel}.swift`: Mailboxes section (Inbox/Today with local counts), Labels section from `Queries.labelsForSheet` (INBOX pinned, STARRED/IMPORTANT/SENT, user labels by visibility rules, Gmail colours, server `threadsUnread`, "Counts from Gmail" footer), selection → `onSelect(.label(id))` + dismiss, `sync.run(.labelOpened(id))` on selection, pull-to-refresh → `refreshLabelCounts(force: true)`, sheet-open staleness check (5 min), chip colour mapping shared with 09 (`LabelChip` view + `[String: LabelRecord]` lookup), `loadOlderLabel` paging hook, `SyncEngine.refreshLabelCounts` + `hydrateLabelView` behaviour verification tests. Public interface: `LabelsScreen(onSelect:)`, `LabelsModel`, `LabelChip`. Must NOT contain: the inbox list itself (09), label sync network code (07 owns it; this module specifies/tests its contract).

## 13-settings-theme-signature — Settings screen, theme picker wiring, signature editor + import, compose style UI, badge toggle, Advanced section
Contains: `Features/Settings/{SettingsScreen,SignatureEditorScreen}.swift`: Form sections of §11 (Account with sign-out, Appearance picker bound to `ThemeStore.choice`, Compose font/size/`ColorPicker`→hex, Signature editor with throwaway `WKWebView` preview via `WebViewHost.makeThrowawayWebView`, `SignatureSanitizer` on save, `data:` image warning, Import from Gmail from `syncState.sendAsSignature`, Use-signature toggle, Reading toggles, badge toggle with `[.badge]` authorization request and self-off on denial, Advanced: sync status line, Full resync now → `requestFullResync`, DEBUG Recent requests from `RequestLog`, version). Public interface: `SettingsScreen`, `SignatureEditorScreen`. Must NOT contain: `Settings`/`SettingsStore`/`ThemeStore` definitions (01), the pooled web view (08).

## 14-qa — Fixtures catalog, stubs, invariant helper, conflict/sync/send tests, smoke tests, device checklist, TestFlight runbook
Contains: the fixture catalog of §13.2 as concrete files with generation notes (JSON shapes per Discovery, `.eml` + `.sha256`, HTML samples), `minimailTests/Support/{StubURLProtocol,TestDatabase,InvariantChecks,FixtureLoader}.swift` conventions (route tables, seeds), `SmokeTests.swift`, `AppEnvironment(testing: true)` wiring, the cross-module test matrix (which module's tests prove which §4.7/§13.3 scenarios; perf tests and their thresholds), `docs/plan/device-checklist.md` (rule lists/CSP/JS toggle/dark mode/BG refresh/badge/quota page/real OAuth items with expected outcomes and fallbacks per §14), and the TestFlight runbook (`make archive` targets, ExportOptions, ASC key secrets, CI job). Public interface: test support types. Must NOT contain: production code changes beyond test hooks already declared in other modules.
